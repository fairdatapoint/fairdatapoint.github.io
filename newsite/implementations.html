Implementations

The primary goal of the FAIR Data Point specifications is to allow developers to create their own FDPs. These new FDPs can be a completely new application or an existint system that has been extended to conform with the FDP specs. Currently, we are aware of the following implementations:

  • FDP Reference Implementation: The FDP implementation from the FAIR Data Team. This implementation includes a server providing API endpoints for the manipulation of the metadata content by other applications, and a Web-based client application for human-centered usage.
  • Molgenis: The MOLGENIS software exposes metadata according to the FAIR Data Point specifications.
  • Castor Electronic Data Capture: The Castor Electronic Data Capture (EDC) allows the users to expose the metadata of the captured clinical trial data following (a previous version of) the FAIR Data Point specifications.
  • FDP-PHP: A PHP implementation for web-based data portals.
  • Netherlands eScience Center: The NL eScienceCenter created a Python prototype of the FDP.
  • CKAN FDP harvester: A CKAN harvester for the FDP.

Our team is composed of passionate researchers and developers from various institutions committed to open science and data-sharing. We believe that by providing a straightforward tool, we can empower the global scientific community to make their data more findable, accessible, interoperable, and reusable, fostering collaboration and innovation.

FDP Reference Implementation

The **FDP Reference Implementation** is a complete, ready-to-use application built to the FDP specification. It's a Spring Boot application that can be deployed easily with Docker. It includes a user interface for managing metadata and a fully functional API for automated access. This implementation serves as a starting point for anyone looking to quickly deploy a FAIR Data Point.
